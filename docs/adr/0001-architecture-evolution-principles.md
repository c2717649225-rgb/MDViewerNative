# ADR-0001：架构渐进演进的原则与已定决策

- 状态：已采纳（2026-09-28）
- 范围：`engine/`、`selftest/`、构建脚本；不含视觉设计文档与产品功能取舍

## 背景

2026-09-28 对 `38e2693` 做了只读分析（源码级依赖图、方法规模、全局状态、异常与持久化核对）：

- `engine` 107 个文件、约 2.3 万行；单项目、单命名空间，分层只靠约定。
- 三个热点仍在增长：`DocView`（含分部）3,813 行，`Program`（含分部）3,124 行，`MdParser` 2,447 行；与上次评审相比，`DocView` +38%，`Program` +21%。
- 真实的循环依赖有三处，其中两处只需挪动四个类型就能拆掉（已用脚本模拟）。
- `preferences.json` 与 `bookmarks.json` 遇到未知 schema 时会被默认值覆盖；草稿（`DraftStore`）已采用正确做法：保留原文件。
- 没有任何检查约束依赖方向；已有的 `ArchitectureTests` 测的是文档流程行为。

## 决策

1. **演进方式**：采用绞杀者、适配层和小切片。每个切片只做一件事，对应一个提交，可以单独 `git revert`。
   - 不重写；不更换解析器；不引入 DI 容器或事件总线；不为每种块机械地生成接口。
2. **怎样证明行为不变**：
   - 纯搬移：靠现有测试，再加本切片新补的契约测试。
   - 替换逻辑：先在自测里做影子对比，新旧实现对同一批语料的输出必须逐字节一致；切换后，旧实现再保留一个切片，然后删除。
   - 只有会改变用户可见行为的修复，才单独立切片，必要时加内部开关。
3. **分层与依赖规则**：从下到上依次是平台、基础设施、领域（内容与工作流）、排版绘制、宿主。
   - 内容与工作流层不得引用 `Win32`、`Dwrite`、`RenderResources`、`DocView`、`Program`、`NativeForm`。
   - 规则由一个轻量自测检查（`selftest/DependencyRulesTests.cs`，E2）。现有违规列进例外清单，清单只减不增；某条例外不再需要时检查也会失败。
   - 按间接可达判断（E19a）：经未分层模块中转到达上层同样算违规。所以不必给每个模块定层，只需列出内容层、工作流层和上层。
   - `EditorSession` 包装 Win32 编辑控件，归为宿主侧；值类型不得定义在视图文件里（比如 `ReadingLocation`，E5 挪出）。
   - 这是本轮唯一新增的常驻检查，理由是防止拆掉的循环再长回来；运行成本不到 1 秒。
4. **数据兼容**：状态文件必须做到“新版能读旧文件，旧版不毁新文件”。
   - 遇到未知 schema 时保留原文件，不覆盖。偏好设置和书签已于 E7 落实（schema > 1 时本次会话只改内存）；草稿原本就是这样；`config.txt` 见 E8、E9。
   - `config.txt` 视为内部契约，写回时保留不认识的键。
   - 持久化格式里带小数点或可能为负的数字显式按 `InvariantCulture` 读写（阅读记忆一直如此，`config.txt` 自 E22 起），不依赖项目的 `InvariantGlobalization` 开关；`hints`、`recentN` 序号这类非负整数在任何区域下写法相同。
   - 读不懂的状态文件（损坏、超过大小上限、字段类型不对、版本号无效）读取时不动，写回前改名保留为 `<文件名>.corrupt-<guid>`；版本号先于其余字段单独读出，未来版本改了字段类型也能认出（E23）。
   - `config.txt` 以后新增的键不要以 `recent` 开头：E24 之前的版本会把所有 `recent*` 键当作最近文件，找不到文件就丢掉。
   - 格式变更必须带版本号，保证能前进也能回滚：旧版读到新字段时只是忽略。
   - 旧版保存时会丢掉同一 schema 内它不认识的字段（E1 已用测试固定）。所以新增字段如果丢失不可接受，必须升 schema；可以丢失的偏好类字段不必升。
5. **会改变行为的修复**：由我按产品定位决定，每项单独一个切片，并在记录里写明新旧差异。
   - 采纳：偏好设置和书签遇到未来版本时保留原文件（E7）；`config.txt` 写回时保留不认识的键（E9）；暂时不在的卷上的最近文件不删除（E10）；打开本地可执行文件前给出更强的提示（E11）；“用当前选区查找”取选区失败时记日志（E12）；重命名后最近文件去重并遵守上限（E16c）；最近文件列表不区分大小写（E21）；读不懂的偏好和书签文件写回前改名保留（E23）；`config.txt` 只认 `recentN` 键、读取时不区分大小写去重（E24）；重新打开过的离线标签关闭后不再恢复（E25）；带备用数据流的链接同样给出可执行警告（E26）。
   - 已决：HTML 导出改用白名单过滤（E14a 做影子对比，E14b 切换），见 ADR-0002。
6. **项目形态**：保持单项目、单命名空间，`engine/` 保持平铺目录。原计划循环清零后按层移动文件，E19b 决定不做：
   - 分层只以 `DependencyRulesTests` 的名单为准，而且已按间接可达检查（E19a）；按层建目录会多出第二份需要同步的分层信息；
   - 移动约 110 个文件，会让 42 份文档里 251 处 `engine/X.cs` 路径失效，自测里十来处写死的 `../engine` 路径也要改，换来的只是浏览时好找一些；
   - 满足以下任一条件时，再评估拆成多个项目，届时按项目一次划好目录，不做两次迁移：出现第二个宿主（例如命令行导出）；或依赖例外长期清不掉。
7. **远端**：2026-09-28 时决定不建远端，本地 `./build.ps1 -Task Verify` 是唯一关卡。该决定于 2026-10-13 由公开发布取代：项目发布到 GitHub 公开仓库，`.github/workflows/ci.yml` 在推送分支和 PR 时执行；本地完整 Verify 仍是提交前关卡。
8. **验证节奏**：迭代时跑 quick，提交前跑一次完整 Verify；涉及窗口行为的切片补跑对应的窗口测试，桌面空闲的规则不变。
   - Verify 运行期间不改工作区（E3 的教训）。
   - 测试改动 `RenderResources` 的全局状态时，统一用 `selftest/RenderStateScope.cs`（E6），不再手写保存和还原。

## 后果

- 每个切片都能单独合并、单独回滚，代价是提交数量较多。
- 第一轮先做低风险切片（契约测试、依赖检查、拆循环），为后面拆 `Program` 和 `DocView` 建立安全网。
- 本 ADR 作废或被替代时，要在这里注明替代它的 ADR 编号。
