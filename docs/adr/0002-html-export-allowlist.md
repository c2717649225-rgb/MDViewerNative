# ADR-0002：HTML 导出的原始 HTML 改用白名单过滤

- 状态：已采纳（2026-09-28，E14b）
- 范围：`HtmlExport` 对 Markdown 中原始 HTML 的导出，包括“导出 HTML”和“复制为 HTML”；不涉及阅读态渲染和解析器

## 背景

- 导出后程序会自动用浏览器打开文件，所以导出里只要残留可执行脚本，打开恶意 Markdown 再导出就会执行它。
- 旧过滤是黑名单：拦 5 种标签，把 `on*` 属性改名，中和 3 种危险协议。它在原文上做局部修改，用的是自己简化的分词。
- E14a 用无头 Edge 实测，证实了 7 个绕过：注释里的引号、无引号属性值里的引号，以及 noscript、xmp、textarea、title、noembed。根源是过滤器与浏览器对同一段文字的切分不一致，继续加黑名单规则只能逐个堵，堵不完。

## 决策

1. 导出默认使用白名单过滤（`HtmlExport.UseAllowlist = true`）：
   - 按 HTML5 分词规则切分，只放行白名单标签和属性，并重新序列化；
   - 白名单外的标签显示为字面文字，与阅读态一致；
   - 注释丢弃；
   - URL 用协议白名单；
   - 属性值里的 `"`、`<`、`>` 一律转成实体。
2. 旧黑名单 `SanitizeRawHtml` 暂时保留，用于回滚和影子对比。确认稳定后，可以另开切片删除。
3. 接受与 CommonMark 的偏差：规范中“原始 HTML 原样直通”的 31 个示例在导出里不再逐字通过，基线相应改为 fail。
   - 理由：本项目以阅读为先，导出是给人看的，不是规范测试器；安全优先于逐字直通；
   - 真实文档里没有正常内容因此被破坏（E14a 语料对比）。
4. 解析器和导出里的 5 种标签拦截维持不变（纵深防御）。

## 后果

- 用户可见的变化：导出和复制为 HTML 时，未知标签（如 `<foo>`）、PHP、CDATA、DOCTYPE 显示为文字；HTML 注释不再出现在导出文件里；`<br />` 等写法被规范化。
- 以后新增白名单标签或属性，需要确认它不是原始文本类、外来内容类（svg、math）、表单类或嵌入类元素，也不是事件属性或会执行的 URL 属性。
- 回滚：把 `UseAllowlist` 的默认值改回 false，并恢复 `selftest/spec-baseline.tsv` 中的 31 行。
